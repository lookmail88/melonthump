## 1. The Model as a File (.ml) 分析模型文件化（.ml）

- **Goal**: lift the analysis model out of the code into a data file that the app loads at runtime — tuning parameters no longer means changing code.

- **目标**：把分析模型从代码里抽出来，变成数据文件，App 运行时加载——改参数不再改代码。

- **Current state**: every threshold and gate is hardcoded in `LocalAnalyzer.swift` (analyzer heuristic-v2.2: dominant frequency <160Hz overripe / 160–280Hz ripe / >280Hz unripe, plus a set of spectral-gate parameters).

- **现状**：判定阈值与门限硬编码在 `LocalAnalyzer.swift`（分析器 heuristic-v2.2：主频 <160Hz 过熟 / 160–280Hz 熟 / >280Hz 生，另有频谱门等一组参数）。

- **Naming (decided)**: the current model is named **Baby 1.0** — the heuristic-v2.2 parameter set once migrated into an .ml file, and the default entry in the model picker.

- **命名（已定）**：现行模型定名为 **Baby 1.0**——即 heuristic-v2.2 参数集迁入 .ml 文件后的正式名字，也是模型选择列表的首发默认项。

- **Requirements**:

- **要求**：

  - The model file uses the **.ml** extension and carries every threshold and gate parameter.

  - 模型文件扩展名定为 **.ml**，承载全部阈值与门限参数；

  - The app loads the model file at launch / analysis time; a missing or corrupt file falls back to built-in default parameters — **it must never crash**.

  - **Model files are externally mounted (decided 2026-11-04)**: beyond the bundled default, .ml files placed in the app's Documents/Models folder (visible through the Files app / Finder) are scanned and mounted read-only at launch, and valid ones appear in the model picker. An invalid external file is skipped entirely — never partially applied. This is the out-of-band channel for adding or updating models without an App Store release.

  - App 在启动/分析时加载模型文件；文件缺失或损坏时回退到内置默认参数，**不许崩**；

  - **模型文件为外部挂载（2026-11-04 定）**：除内置默认模型外，放进 App 的 Documents/Models 文件夹（经"文件"App / Finder 可见）的 .ml 文件，在启动时被扫描并以只读方式挂载，校验通过的出现在模型选择列表里。无效的外部文件整份跳过，绝不部分生效。这是不发新版即可新增/更新模型的带外通道；

  - The file format is finalized during this release's design phase and must include a version field.

  - 文件格式在本版设计阶段定稿，必须带版本号字段；

  - **The default model is free (decided 2026-11-04)**: the default model (Baby 1.0) is free for every user, permanently — no unlock, no purchase, no credit requirement.

  - **A paid model (decided 2026-11-04)**: alongside the free default, at least one **paid model** is offered, delivered as a StoreKit in-app purchase. Its name, price, and what makes it better are TBD (see Open Questions). It does **not** ship in 1.2.0 (decided 2026-11-04: free first — 1.2.0 launches with the free model only; the paid model follows in a later release). Note: this deliberately revises the earlier ads-only stance for the model line — the app itself stays free and ad-supported; only extra models may charge.

  - **Model rotation (decided 2026-11-04)**: the paid slot always holds the current latest model. When a newer model ships, the previously-latest model becomes a free version; the **default model (Baby 1.0) is always kept** and always free. Users who bought a model keep it permanently.

  - The loading interface must leave a seam for swapping in a real machine-learning model later: same interface, replaceable implementation.

  - **默认模型免费（2026-11-04 定）**：默认模型（Baby 1.0）对所有用户永久免费——不需解锁、不需购买、不耗 credit；

  - **再提供一个收费版模型（2026-11-04 定）**：在免费默认版之外，至少再提供一个**收费版模型**，走 StoreKit 内购。其名称、定价、强在哪儿待定（见待定事项）。它**不进 1.2.0**（2026-11-04 定：先上免费版——1.2.0 首发只有免费模型，收费版后续版本再加）。注意：这是对先前"只靠广告"口径的一次明确修订——App 本体仍免费+广告，只有额外的模型可以收费；

  - **模型轮换（2026-11-04 定）**：收费位永远放当前最新模型。新模型上线后，上一代最新模型转为免费版；**default 版（Baby 1.0）始终保留**、始终免费。已购买某模型的用户永久保留该模型；

  - 加载接口要为将来替换成真正的机器学习模型留接缝：接口不变、实现可换；

  - Multiple models may coexist (different versions, different models); the user switches between them in the hamburger menu's model picker (see §2). The picker lists every available model with its state — Default / Free / Paid (price shown, or Purchased) — switching to a free model takes effect immediately; choosing the not-yet-purchased latest model runs the StoreKit purchase first.

  - 模型可多份共存（不同版本、不同模型），用户在汉堡菜单的"模型选择"里切换（见 §2）。列表里每个模型都标状态——Default / 免费 / 收费（未购显示价格、已购显示已购买）；选免费模型立即生效，选尚未购买的最新模型先走 StoreKit 购买流程；

  - The bundled default model ships with app releases; additional models arrive as externally mounted files (above), not by server delivery — server-side delivery is **not** done (decided 2026-11-04).

  - 内置默认模型随 App 版本发布；其余模型走外部挂载文件（见上条），不走服务端——服务端下发**不做**（2026-11-04 定）。

- **Not in this release**: no trained CoreML model — this step is only "parameters as data".

- **本版不做**：不引入训练出来的 CoreML 模型，只做"参数即数据"这一步。

## 2. UI Upgrade (Structure & Interaction Only; Art Frozen) UI 升级（只动结构与交互，美术冻结）

- **Art freeze (hard rule)**: Stephanie's original artwork — the watermelon, every cat's design, the color palette, all existing screen elements — **stays completely untouched, not one pixel redrawn**. New elements follow the app's existing design language; no foreign style is introduced.

- **美术冻结（硬性要求）**：Stephanie 的原创美术设计——西瓜、每只猫的造型、配色、现有画面元素——**完全不动，一像素不改**。新增元素的视觉风格参照 App 现有设计语言，不引入外来风格。

- **Top bar**:

- **顶部栏改造**：

  - **Top-left**: a hamburger button (three lines; interaction modeled on the Muse app's top-left menu button).

  - **左上角**：汉堡菜单按钮（三条横线，交互形态参照 Muse App 左上角的菜单按钮）；

  - **Top-right**: an Invite button (entry point modeled on the Muse app's top-right invite button).

  - **右上角**：Invite 按钮（入口形态参照 Muse App 右上角的邀请按钮）；

  - The top bar must not cover any existing artwork; exact placement is mocked up in the design phase and built only after the user's confirmation.

  - 顶部栏不得遮挡原有美术元素，具体位置在设计阶段出图，经用户确认后再施工。

- **Hamburger menu**: tapping opens a slide-in drawer. Decided contents: a **Model picker** — switches the .ml model used for analysis (paired with the model-as-file work in §1), persisted locally and effective from the next analysis; a **Settings** entry — Language and Listening Duration live under Settings (see below); an **About** entry (app version, privacy policy, terms of service, contact, and a link to the project's GitHub README — github.com/lookmail88/melonthump — opening in the browser). Menu contents are final (decided 2026-11-04): no History entry. The Settings page is modeled on Retax's Settings page: it holds the Language picker, Listening Duration, the Feedback entry, and (when unlocked) the Server selector — see the bullets below.

- **汉堡菜单**：点击展开侧边抽屉式菜单。已定内容：**模型选择选项**——切换分析所用的 .ml 模型文件（与 §1 模型文件化对应），选择本地持久化、对下一次分析即时生效；**Settings（设置）选项**——Language（语言）与侦听时长归入 Settings 之下（见下条）；**About（关于）选项**（内容：App 版本号、隐私政策、服务条款、联系入口、GitHub README 链接——github.com/lookmail88/melonthump，点击在浏览器打开）。菜单内容已定稿（2026-11-04 定）：不加历史记录。Settings 页照搬 Retax 的设置结构：内含语言选择、侦听时长、用户建议入口，以及（解锁时）服务器选择——见下面各条。

- **Languages (i18n)**: app UI strings ship in three languages — **Simplified Chinese, English, Español**. The default follows the system language; switching under Hamburger → Settings → Language persists locally, takes effect immediately, and needs no app restart. Scope is UI text strings only; text baked into artwork is out of scope (art freeze).

- **多语言（i18n）**：App UI 文案支持三种语言——**简体中文、English、Español**。默认跟随系统语言；用户在汉堡菜单 → Settings → Language 里切换后，本地持久化、即时生效、不重启 App。本地化范围只限 UI 文案字符串，美术图内嵌的文字不在范围内（美术冻结）。

- **Listening duration (Settings)**: Settings gains a **Listening Duration** entry with three options — **3s, 5s (default), 8s** — persisted locally and effective from the next recording. It sets the length of the recording window (currently hardcoded at 5s, which stays the default); the on-screen countdown follows the chosen value. The option labels are UI strings and localize together with the i18n work above.

- **Feedback (ported from Retax's Settings)**: Settings gains a **Feedback** entry （意见与建议）, placed above About exactly as in Retax (Retax commit `550b315`). Tapping it opens the system mail composer pre-addressed to the MelonThump support mailbox — **support@stephaniegao.me** (Cloudflare Email Routing forwarding to lookmail88@gmail.com, live and test-verified 2026-11-04, mirroring support@retax.cc) — with the subject prefilled ("MelonThump Feedback") and the app version appended to the body. Feedback travels by email only — no server endpoint, nothing stored — matching Retax's stateless approach and MelonThump's no-account design.

- **侦听时长（Settings）**：Settings 新增"侦听时长"条目，三个选项——**3 秒、5 秒（默认）、8 秒**——本地持久化，对下一次录音生效。它决定录音的侦听窗口长度（现行写死 5 秒，默认值与之对齐）；界面上的倒计时跟随所选值。选项文案属于 UI 字符串，随上文多语言一并本地化。

- **用户建议（照搬 Retax 设置）**：Settings 新增"意见与建议"入口，位置与 Retax 一致——放在「关于」上方（Retax 提交 `550b315`）。点开拉起系统邮件撰写界面：收件人预填 MelonThump 支持邮箱 **support@stephaniegao.me**（Cloudflare Email Routing 转发到 lookmail88@gmail.com，2026-11-04 已实测开通，照 support@retax.cc 的做法）、主题预填（"MelonThump 意见反馈"）、正文末尾自动附 App 版本号。反馈只走邮件、不经服务端、不存任何东西——与 Retax 的无状态口径及 MelonThump 的无账号设计一致。

- **Server selector unlocked by server-published versions (a gated exception to the channel lock)**: at launch the app compares its own version (`CFBundleShortVersionString`) against two values published in the server's version policy — a "TestFlight version" and a "Product version" (the current App Store release; field names finalized in the design phase; newly added optional fields, backward compatible). The **Settings page shows a Server selector entry** (Dev / Prod; default Prod; the choice persists, as today) **only when the app version equals the TestFlight version and differs from the Product version**. (Placement decided 2026-11-04: the selector moves into Settings together with Language and Feedback, per the Retax Settings layout — it no longer sits at the bottom of the home screen. Xcode builds, where the selector exists today, likewise reach it through Settings.) If the TestFlight version equals the Product version — that version has graduated to production — the selector is never shown, to anyone. The same holds on any other mismatch, or if the policy cannot be fetched: non-Xcode builds stay locked to Prod and no selector is rendered. Flipping the Product version at release (already a step in the standing release-order policy flip) therefore closes this gate automatically. Purpose: a TestFlight build can be pointed at the dev server for testing, without ever exposing the switch to store users.

- **服务端版本号解锁服务器选择框（渠道锁定的门控例外）**：App 启动时把自己的版本号（`CFBundleShortVersionString`）与服务端版本策略下发的两个值比对——"TestFlight 版本号"与"Product 版本号"（即当前 App Store 正式版；字段名设计阶段定；新增可选字段、向后兼容）。**仅当 App 版本 == TestFlight 版本号、且 != Product 版本号时**，Settings 页里才显示服务器选择条目（Dev / Prod；默认 Prod；选择持久化，与现行一致）。（位置 2026-11-04 定：选择器随语言、用户建议一并收进 Settings，照 Retax 设置布局——不再放在主页底部。Xcode 包现行有选择器的，同样改走 Settings 入口。）若 TestFlight 版本号与 Product 版本号一致（该版本已转正），对任何人都不显示；其余不一致、或策略拉取失败时同样不显示，维持现行行为——非 Xcode 渠道锁定 Prod、不渲染选择框。发布时翻 Product 版本号本就是发布顺序里翻版本策略的一步，此门由此自动关闭。目的：让 TestFlight 版本可以切去测 dev 服务器，且永远不把这个开关暴露给商店用户。

(Versus the earlier three-line version: Architecture: Xuyang Gao is kept, Project Owner: Xuyang Gao is added, and Coder: Pepper splits into Developer: Claude for the coding and BA/QA: Muse for requirements and QA.) The credits are UI text (they localize with the i18n work above; the names themselves are not translated) and sit low on the launch screen, near the bottom, clear of Stephanie's artwork; the fine placement is confirmed with a design-phase mock-up, same as the top bar.

## 3. Invite (Modeled on Muse's Invite) Invite 功能（机制参照 Muse 的邀请）

Modeled on Muse's invite mechanism, an isomorphic feature for MelonThump:

参照 Muse 邀请机制，为 MelonThump 设计同构的功能：

- **Invite credentials**: every user has their own invite credential in two forms — an invite link and an invite code.

- **邀请凭据**：每个用户有自己的邀请凭据，两种形态——邀请链接 + 邀请码；

- **Sharing**: tapping the top-right Invite button opens the system share sheet; the link / code goes out over Messages, WeChat, Mail, and other system channels.

- **分享路径**：点右上角 Invite 按钮 → 拉起系统分享面板，把邀请链接/邀请码经短信、微信、邮件等系统渠道发给朋友；

- **Invitee path**: a friend installs and opens the app via the invite link, or enters the invite code in the app → the system confirms one valid invite. Sharing, installing, and confirming are three separate steps; merely opening the link does not count as confirmation.

- **被邀请人路径**：朋友通过邀请链接安装并打开 App，或在 App 内输入邀请码 → 系统确认一次有效邀请。分享、安装、确认是三个独立步骤，点开链接本身不算确认；

- **Reward (decided 2026-11-04)**: once an invite is confirmed, the **inviter receives +5 credits** and the **invitee also receives +5 credits**, wired into the existing CreditWallet. The per-user cap is **10 confirmed invites**. A "valid invite" requires the invitee to **complete their first thump analysis**. (The 1.2.0 credit economy is defined by the post-promotion rule below.)

- **奖励（2026-11-04 定）**：邀请确认成立后，**邀请人得 +5 credit、被邀请人也得 +5 credit**，与现有 CreditWallet 打通。每人邀请上限 **10 次**。"有效邀请"的确认条件：**被邀请人完成首次拍瓜分析**。（1.2.0 的 credit 经济以下文推广期后规则为准）；

- **Post-promotion starting allowance (decided 2026-11-05)**: when the credit economy resumes in 1.2.0 (after the promotion ends), **every user — new and existing, unconditionally — gets their first two thumps free, no ad required**: the first analysis is never charged, and each user is granted **1 credit**, which covers the second. **From the third thump on** (refined 2026-11-05), the user watches **one rewarded ad**, which unlocks **unlimited thumps for the rest of that app session** — no further ads until the app is closed and relaunched, when the gate re-arms (the promotion's session mechanic, made permanent). This supersedes the CreditWallet v1 welcome grant of 5 and its per-analysis charging for the 1.2.0 era. Credits buy ad-free use (decided 2026-11-05): at the session gate, a user with balance may spend **1 credit to unlock that session with no ad** — so invite rewards (+5/+5) are worth five ad-free sessions each.

- **Ad strategy is server-tunable, no recompile (decided 2026-11-05)**: the whole allowance policy — the number of initial free thumps, the session-unlock gate, and the credit price of an ad-free session — is driven by parameters issued through the existing server policy channel (the version-policy endpoint that already carries `creditPerAd` and `promoEndsAtEpochMillis`), so strategy changes take effect by editing server configuration only, never by recompiling or re-releasing the app. The client ships with the values decided here as built-in defaults and falls back to them when the policy cannot be fetched (fail-open, consistent with VersionGate).

- **推广期后的起始额度（2026-11-05 定）**：1.2.0 中 credit 经济恢复后（推广期结束），**所有用户——新老一视同仁、无条件——头两次拍瓜免费、无需看广告**：首次分析免扣，另每人送 **1 个 credit**，正好覆盖第二次。**第三次起**（2026-11-05 细化）：看**一支激励广告**即解锁**本次打开 App 期间的无限次拍瓜**——关掉重开后闸门重新生效、本次打开内不再看广告（即推广期的会话机制转为常态）。本条取代 CreditWallet v1 的欢迎赠 5 与按次扣费（1.2.0 时代口径）。credit 的用途定为免广告（2026-11-05 定）：到会话闸门时，有余额的用户可花 **1 credit 免广告解锁当次会话**——邀请奖励（+5/+5）即等于五次免广告会话；

- **广告策略走后台参数、无需重新编译（2026-11-05 定）**：整套额度策略——起始免费次数、会话解锁闸门、免广告会话的 credit 价格——全部由现有服务端策略通道下发（即已承载 `creditPerAd` 与 `promoEndsAtEpochMillis` 的版本策略接口），改策略只改服务端配置，永不重新编译或发版。客户端内置本文所定数值作为默认值，拉不到策略时回退默认（fail-open，与 VersionGate 一致）；

- **Anti-abuse**: invite confirmations must be recorded and verified server-side (reusing the stats persistence and App Attest gating built in 1.1.0); duplicate invites from the same device / install are never double-counted.

- **防刷**：邀请确认必须经服务端记录与校验（复用 1.1.0 已建的统计落库与 App Attest 门控）；同一设备/同一安装的重复邀请不重复计奖；

- **Privacy boundary**: an invite is install attribution plus a reward — no user data is shared with anyone.

- **隐私边界**：邀请只是安装归因 + 发奖，不涉及任何用户数据互通。

## 5. Standing Rules 不变的规矩

- Server backward compatibility: response fields are only ever added as optional; `/api/v1` semantics never break.

- 服务端向后兼容：只增可选字段、`/api/v1` 语义永不破；

- Release order: server code deploys first (policy pinned to the old version) → TestFlight verifies against prod → App Store submission, review, manual release → version policy flips only after the new build is downloadable.

- 发布顺序：服务端代码先行部署（策略钉住旧版）→ TestFlight 连 prod 验证 → App Store 提交过审、手动发布 → 新版可下载后才翻版本策略；

- Local build and the full test suite must pass before any commit; work happens only on the development branch, and main accepts PRs only.

- 本地编译/全量测试通过才能 commit；只在 development 分支施工，main 只接受 PR。
