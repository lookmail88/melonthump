# MelonThump 2.0 Development Checklist / 开发清单

> Derived from `docs/2.0-design.md` v0.37 (2026-11-08) — all §7 open questions are closed; section references point at the design doc. Nothing here starts until the user gives the build go-ahead.
> 依据 `docs/2.0-design.md` v0.37（2026-11-08）——§7 开放问题已全部关闭，条目后的章节号指设计文档。用户明确开工前，本清单不动工。

## 0. Prerequisites & calibration banking / 前置与标定攒样

- [ ] Keep banking in-house samples per the §5 protocol (kitchen scale, equator knocks ≥3, four parts complete) toward the 30-sample threshold (§7 item 2)
  按 §5 协议持续攒自家样本（厨房秤实称、赤道位 ≥3 拍、四部分齐全），向 30 只门槛推进（§7 第 2 条）

## 1. Data & modeling / 数据与建模

- [ ] Texture-feature pipeline: decay characteristics, spectral shape, crest distribution, f²·m (dominant frequency alone cannot grade texture — §4)
  质地特征管线：衰减特性、谱形、crest 分布、f²·m（主频分不出质地——§4）
- [ ] Photo weight estimation prototype: bank-card detection and size estimation from the whole-melon photo; measure error against scale readings (§7 item 3)
  照片估重原型：整瓜照中银行卡检测与尺寸估算；与秤读数比对测误差（§7 第 3 条）
- [ ] Fusion experiment: rind-texture features vs acoustic-only, blind test — fusion ships only if it beats acoustic-only (§6)
  融合实验：瓜皮纹理特征 vs 纯声学，盲测——融合胜出才以融合口径上线（§6）
- [ ] At ≥30 complete scored samples: offline modeling experiments; validation gates — score MAE ≤8 points, three-band verdict no regression; if a gate fails, retest at 50, 80 (§6, §7 item 2)
  全样本满 30 只：启动离线建模实验；验证门——打分 MAE ≤8 分、三档判定不回退；不过门则 50、80 再测（§6、§7 第 2 条）
- [ ] Produce the new .ml scoring model file (versioned, appears in the in-app model list; the 2.0 scoring model is free — §7 item 6)
  产出新的 .ml 打分模型文件（版本化、进 App 模型列表；2.0 打分模型免费——§7 第 6 条）

- [ ] **Fix the home hero art artifact** (§2 home screen; reported by the owner 2026-11-08 with a screenshot): the `HeroMelon.png` cutout caught the left edge of the orange cat from the original composition at the canvas's right edge — a ~12 px orange sliver (asset x 458–469, y 259–330) floats beside the melon slice. Fix = erase the fragment pixels only (cutout cleanup, no redrawing, artwork otherwise untouched). A cleaned asset is already prepared and visually verified by Pepper (workspace `melonthump/hero-fix-HeroMelon.png`); drop it into the imageset with the iOS package on branch `2.0` and verify on the home screen.
  **修首页主图美术残留**（§2 首页；机主 2026-11-08 截图指出）：`HeroMelon.png` 抠图时把原图构图里橙猫的左边缘带进了画布右缘——西瓜片旁漂着一条约 12 px 宽的橙色碎片（资源坐标 x 458–469、y 259–330）。修法 = 只擦除碎片像素（抠图清理、不重绘、其余画面不动）。清理好的资源 Pepper 已备好并目视验过（工作区 `melonthump/hero-fix-HeroMelon.png`）；随 iOS 包在 `2.0` 分支落入 imageset，并在首页实测确认。

- [ ] Melon record data layer (§2 item 8): one reopenable on-device record per melon — appearance photos, recordings, verdict + score, bookkeeping (variety, weight + provenance, source, date); records list serves as the user's thump history
  瓜记录数据层（§2 第 8 条）：每只瓜一条可重开的本机记录——外观照、录音、判定＋分数、簿记（品种、重量＋来源标记、来源、日期）；记录列表即用户的拍瓜历史
- [ ] Unified capture flow (§5 item 1): texture close-ups + whole-melon shot (bank-card prompt) + recordings, identical for all users; variety by picker only — seedless / seeded / mini / yellow-flesh / Kirin / Black Beauty / other-not-sure, no free-text field (§7 item 7)
  统一采集流程（§5 第 1 条）：纹理近摄＋整瓜照（银行卡提示）＋录音，全员一致；品种只点选——无籽/有籽/迷你/黄瓤/麒麟/黑美人/其他-不清楚，无自由输入框（§7 第 7 条）
- [ ] Weight capture: photo estimation or manual entry, provenance marked (estimated vs scale-measured), never a required field (§7 item 3)
  重量采集：照片估重或手工输入，带来源标记（估重 vs 实称），永不设为必填（§7 第 3 条）
- [ ] Scoring integration: run the new .ml model on-device; no-mass fallback path with marked-down confidence when weight is absent (§7 item 3)
  打分接入：新 .ml 模型本地运行；缺重量时走无重量降级路径并标注置信度降低（§7 第 3 条）
- [ ] Result page rework (§7 item 5): score primary, three-band verdict as a secondary label; low score confidence hides the number and the band becomes primary. Artwork untouched — structure/interaction only
  结果页改版（§7 第 5 条）：分数为主、三档为小标签；分数置信度低时不显示数字、切回三档为主。美术不动——只改结构与交互
- [ ] Contributor identity: generate the dedicated contributor UUID at opt-in, stored in Keychain, separate from the stats installId (§5 item 6)
  贡献者身份：开通时生成专属贡献者 UUID、存 Keychain，与统计 installId 分开（§5 第 6 条）
- [ ] Recruitment entry (ships with 2.0 only): "Join the Model Improvement Program" in Settings → explanation page (four parts, ad-free earnings, privacy wording per §7 item 8) → enrollment note → application submission (§5 item 6)
  招募入口（只随 2.0 上线）：Settings「参与模型提升计划」→ 说明页（四部分、免广告激励、隐私口径同 §7 第 8 条）→ 留言 → 提交申请（§5 第 6 条）
- [ ] Contributor appends: cut-open photo + feedback on the same melon record — feedback = 0–100 score + taste TAGS (multi-select presets, no free text) + three-band truth (§5 item 1, §7 items 7/10)
  贡献者补件：在同一条瓜记录上补切开图＋反馈——反馈＝0–100 评分＋口感标签（预置多选、不自由填）＋三档真值（§5 第 1 条、§7 第 7/10 条）
- [ ] Contributor self-service area: submission list, review status (incl. return reason), completeness, withdraw/delete own submissions, ad-free balance (§5 item 6)
  贡献者自助区：提交列表、审核状态（含退回原因）、完整度、撤回/删除自己的提交、免广告余额（§5 第 6 条）
- [ ] adExempt client support (§2 item 6): send install_id with the policy request, honor `adExempt` and the countable ad-free allowance — may ship earlier in a 1.2.x patch
  adExempt 客户端支持（§2 第 6 条）：策略请求带 install_id、执行 `adExempt` 与可计数免广告余额——可提前到 1.2.x 补丁版
- [ ] Privacy: App Store privacy label update + in-app privacy explanation, one wording everywhere (§7 item 8)
  隐私：App Store 隐私标签更新＋App 内隐私说明，全站一套话（§7 第 8 条）
- [ ] Backward-compatibility check: /api/v1 semantics unchanged; older clients unaffected by every new field (additive optional only)
  向后兼容自查：/api/v1 语义不变；所有新字段只增可选，旧客户端行为不受影响

## 3. Server / 服务端

- [ ] Contributor & sample data layer: contributor records (ID, enrollment note, status), sample records with four-part completeness, void-marking instead of physical deletion, audit fields (§5 item 6, §7 item 10)
  贡献者与样本数据层：贡献者记录（ID、开通留言、资格状态）、样本记录（四部分完整度）、剔除作废标记而非物理删除、审计字段（§5 第 6 条、§7 第 10 条）
- [ ] Contribution APIs: application submission, sample upload (fields limited to the §7 item 8 list), self-service queries (status / completeness / balance), withdraw/delete with true deletion of server materials (backups age out ≤30 days)
  贡献接口：申请提交、样本上传（字段限死为 §7 第 8 条清单）、自助查询（状态/完整度/余额）、撤回/删除时服务端素材真删（备份 30 天内过期）
- [ ] Material file service: photo/recording storage on the project's own server, signed access for admin viewing/playback (§7 item 8, §2 item 7)
  素材文件服务：照片/录音存自家服务器，管理页经签名链接查看/播放（§7 第 8 条、§2 第 7 条）
- [ ] Preliminary-review support (§7 item 10): store Pepper's per-sample recommendation (suggest-approve / suggest-return + drafted reason / flag) for the admin queue; preliminary actions written to the audit log
  初审支持（§7 第 10 条）：为管理页待审队列存 Pepper 的逐样本初审意见（建议通过/建议退回＋原因草稿/存疑）；初审动作进审计日志
- [ ] Admin REST APIs (separate from /api/v1): (A) contributor applications, roster, status toggles, contributor detail; (B) sample review — approve / return-with-reason / void, completeness flags, material viewing; (C) adExempt list, ad-free grants, operational ad switches; (D) read-only overview (§7 item 11)
  管理 REST 接口（与 /api/v1 分开）：（A）贡献者申请、名单、资格开关、详情；（B）样本审核——通过/退回（带原因）/作废、完整度标记、素材查看；（C）豁免名单、免广告发放、运营广告开关；（D）只读概览（§7 第 11 条）
- [ ] Policy extension: `adExempt` + ad-free allowance in the policy response; release-class numbers (latestVersion, minSupportedVersion) stay OUT of admin editing — release process only (§7 item 11)
  策略扩展：策略响应加 `adExempt` 与免广告余额；发布类数字（latestVersion、minSupportedVersion）不进管理页编辑——只走发布流程（§7 第 11 条）
- [ ] Incentive ledger (§7 item 9): +5 ad-free units per approved complete sample (admin-adjustable parameter), clawback of unused units on voiding, kept as a separate book from the Invite credit economy
  激励记账（§7 第 9 条）：每份审核通过的全样本＋5 次免广告（管理页可调参数），作废时追回未用部分，与 Invite credit 两套账分开
- [ ] Audit log: minimal append-only record of every admin change (who via Cloudflare Access identity, when, object, before/after) (§7 item 11)
  审计日志：所有管理变更的最小版 append-only 流水（谁＝Access 身份、何时、对象、改前改后）（§7 第 11 条）

  按 §7 第 11 条清单做 A–D 页；待审队列展示 Pepper 初审意见（§7 第 10 条）

  响应式布局，Safari/Chrome/Edge 实测（§2 第 7 条）

## 5. Release / 发布（按发布顺序铁律）

- [ ] **Admin API stays dark until Cloudflare Access covers it (deployment gate from S3)**: keep `MELONTHUMP_ADMIN_ENABLED` unset/false in prod (and dev) until the Access policy for `/api/admin/**` is verified live; only then set it to `true`. The admin REST API itself has no login — Access at the edge is the only authentication.
  **管理接口在 Cloudflare Access 覆盖前保持关闭（S3 带来的部署门）**：`/api/admin/**` 的 Access 策略实测生效前，prod（及 dev）的 `MELONTHUMP_ADMIN_ENABLED` 保持未设/false，之后才置 `true`。管理 REST 接口本身没有登录——边缘的 Access 是唯一认证。

- [ ] **Persistent volume for contributed materials (deployment requirement from S2)**: prod (and dev, if samples there must survive restarts) must mount a persistent volume at `MELONTHUMP_CONTRIB_STORAGE_DIR` before the contribution APIs are enabled — the default in-container `contrib-materials/` directory is lost on pod restart. With more than one replica the volume must be shared (RWX) or uploads pinned to a single replica; also confirm the ingress request-body limit accepts the 100 MB upload cap.
  **贡献素材持久卷（S2 带来的部署要求）**：贡献接口启用前，prod（dev 若需样本跨重启保留亦然）必须在 `MELONTHUMP_CONTRIB_STORAGE_DIR` 挂持久卷——默认的容器内 `contrib-materials/` 目录在 Pod 重启后即丢失。多副本时卷须共享（RWX）或上传固定单副本；并确认 ingress 请求体上限容得下 100 MB 上传上限。

- [ ] Prod server deployed first → TestFlight build verified against prod → App Store submission & manual release → version-policy numbers flipped only after 2.0 is downloadable
  prod 服务端先行 → TestFlight 连 prod 验证 → App Store 提交并手动发布 → 2.0 可下载后才翻版本策略数字
- [ ] Store listing refresh for 2.0 (post-promo wording; the 2026 launch promo has ended)
  商店页文案换 2.0 版（推广后口径；2026 推广期已结束）
- [ ] Post-release: first data review of contributed samples and review-queue throughput
  发布后：首轮共建样本数据复盘与审核队列吞吐检查

## Out of scope for 2.0 / 不在 2.0 范围

- External audio hardware; paid models (first paid model is 3.0's tuned model — §7 item 6); dataset export (3.0); per-user management of ordinary users; GraphQL admin APIs
  外部音频硬件；付费模型（首个付费模型是 3.0 调优模型——§7 第 6 条）；数据集导出（3.0）；普通用户按人管理；管理接口 GraphQL 化
