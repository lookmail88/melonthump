## 1. System Architecture (Current) 系统架构（现行定版）

Tap analysis runs entirely on the iPhone; recordings are never uploaded:

拍瓜分析全部在 iPhone 本地完成，录音不上传服务器：

```
iPhone App ──record (AVAudioEngine)──► LocalAnalyzer (on-device analysis)──► Result screen 结果页
     │
     └──at launch, query──► Server (two jobs only: health check + client version policy)
```

- **Client**: a native SwiftUI app (bundle id `dev.xuyang.melonthump`).

- **客户端**：SwiftUI 原生 App（bundle id `dev.xuyang.melonthump`）。

- **Server**: Spring Boot (Java 25) keeping only `health` + the client version query + Swagger; the original analysis stack has been removed.

- **服务端**：Spring Boot（Java 25），只保留 `health` + 客户端版本查询 + Swagger；原分析栈已删除。

- **Environments**: prod `melonthump.stephaniegao.me` / dev `melonthump-dev.stephaniegao.me`; the app has a Prod/Dev server picker (segmented control, display names only, Prod by default).

- **环境**：prod `melonthump.stephaniegao.me` / dev `melonthump-dev.stephaniegao.me`，App 内有 Prod/Dev 服务器选择器（分段控件，只显示名称，默认 Prod）。

Architecture history: v1 originally uploaded recordings for server-side analysis; late on 2026-10-20 the design was settled to on-device analysis (works offline, instant results, zero server compute cost), and the server became policy-delivery only.

架构变迁：v1 原为"上传服务端分析"，2026-10-20 深夜定版改为本地分析（离线可用、结果即时、无服务器算力成本），服务端转为纯策略下发。

## 2. iOS Client iOS 客户端

### 2.1 Recording 录音

- `AudioRecorder` is built on AVAudioEngine (an installTap capture); the session runs in `.measurement` mode (system voice processing / AGC off, so the noise floor stays stable for the analyzer), and session pre-activation happens on a background thread (activating on the main thread caused UI-unresponsiveness logs).

- `AudioRecorder` 基于 AVAudioEngine（installTap 采集）；会话使用 `.measurement` 模式（关掉系统语音处理与自动增益，底噪电平稳定、利于分析），会话预激活放在后台线程（在主线程激活曾导致 UI 卡顿日志）。

- Recording is a 5-second countdown shown large on the recording screen: it stops automatically at 0 and goes straight to analysis; the user may stop manually once past 3 seconds (the Stop & Analyze button is disabled before that). The recording screen shows a live microphone-level waveform.

- 录音为 5 秒倒计时（录音页大号显示）：到 0 自动停止并直接进入分析；超过 3 秒后用户可手动停止（Stop & Analyze 按钮此前禁用）。录音页有麦克风实时电平波形显示。

- Historical pitfall: WAV files written by AVAudioRecorder carry a WAVE_FORMAT_EXTENSIBLE header; a hand-rolled parser that only accepted format=1 rejected real-device recordings (415). Recording now goes through AVAudioEngine and decoding through AVAudioFile, natively compatible with every variant.

- 历史坑：AVAudioRecorder 写出的 WAV 是 WAVE_FORMAT_EXTENSIBLE 扩展头，手写解析器只认 format=1 曾导致真机录音被拒（415）；现录音走 AVAudioEngine、解码走 AVAudioFile，原生兼容所有变体。

### 2.2 On-Device Analysis Pipeline (LocalAnalyzer, heuristic-v2.2) 本地分析管线（LocalAnalyzer，heuristic-v2.2）

Design principle: first prove a credible thump happened — any doubt returns `UNKNOWN` ("no clear thump heard") instead of forcing a verdict.

设计原则：先证明"确实听到了一次敲击"——任何一关存疑就返回 `UNKNOWN`（没听到敲击），不硬猜。

1. **Envelope gates (time domain)**: a 10 ms RMS envelope; the peak is searched only in the usable window (0.3 s after start to 0.2 s before the end, excluding start/stop handling transients). Required: peak ≥ ~−45 dBFS absolute; peak width ≥ 2 frames at half-peak (single-frame clicks rejected); prominence ≥ 10 dB over the median envelope (the noise floor); attack (half-peak → peak) ≤ 80 ms; decay to 1/e ≤ 800 ms, and a sound still loud at the end of the clip counts as sustained, not a thump.

   **包络门（时域）**：10ms RMS 包络；峰值只在可用窗口内搜索（开始后 0.3s 到结束前 0.2s，排除起止时的拿放瞬态）。要求：峰值绝对电平 ≥ 约 −45 dBFS；半峰宽 ≥ 2 帧（单帧咔哒声拒绝）；峰值高出中位包络（底噪）≥ 10 dB；上升沿（半峰→峰值）≤ 80ms；衰减到 1/e ≤ 800ms，且响到录音结束还不衰减的按持续音处理、不算敲击。

2. **Spectrum (frequency domain)**: FFT of the 500 ms segment starting at the thump, Hann window, dominant frequency searched in the 60–600 Hz melon band.

   **频谱（频域）**：取敲击处 500ms 段做 FFT（Hann 窗），主频搜索限定 60–600Hz 瓜声频带。

3. **Spectral gates**: local crest — the peak must tower ≥ 18 dB over its own 15–75 Hz neighbourhood (a resonance is one sharp line; broadband desk knocks and handling bumps are smooth humps and fail); spectral SNR ≥ 6 dB against a noise-only segment's spectrum; ring consistency — a clear tone still audible later in the ring must match the main pitch within 15%.

   **频谱门**：局部尖锐度——主峰须高出其左右 15–75Hz 邻域 ≥ 18 dB（共振是一根尖线；宽带的桌面敲击、拿放摩擦是平滑能量丘、过不了）；与纯噪声段频谱比的 SNR ≥ 6 dB；余振一致性——衰减后段还能听清的音高须与主频一致（±15%）。

4. **Classification (placeholder thresholds, uncalibrated)**: dominant frequency <160 Hz overripe / 160–280 Hz ripe / >280 Hz unripe; confidence is a heuristic mapping of distance to the band edges (0.55–0.95). The result screen also shows a small debug line with every gate's measured values, so a wrong verdict can be traced to the exact gate that leaked.

   **分类（占位阈值，未校准）**：主频 <160Hz 过熟 / 160–280Hz 熟 / >280Hz 生；置信度为距边界距离的启发式映射（0.55–0.95）。结果页另有一行小字调试信息，列出每道门的实测值，误判时可定位是哪道门漏的。

Validation: a Python mirror of the same logic passes 16 synthetic cases (quiet/loud noise, hum, slow swells, start pops, digital clicks, broadband desk knocks, HVAC switch-on → all UNKNOWN; damped bursts at 140/200/320 Hz, even weak ones → correct verdicts). Field iteration on a real device drove v2 → v2.1 → v2.2 within 2026-10-21.

验证方式：同逻辑的 Python 镜像版在 16 个合成样本上全过（安静/吵闹噪声、嗡嗡声、缓慢渐强、启动爆音、数字咔哒、宽带桌面敲击、空调启动 → 全部 UNKNOWN；140/200/320 Hz 衰减脉冲、包括很弱的 → 判定正确）。2026-10-21 当天由真机实测驱动了 v2 → v2.1 → v2.2 三轮迭代。

Superseded: heuristic-v1.1 (high-pass at ~55 Hz + spectral subtraction + SNR gate, shipped 2026-10-21 in `32fd6b0`) tried to rescue thumps buried in noise by subtracting the room spectrum. Real-device tests showed noise-only recordings still produced verdicts, so v2 replaced the rescue approach with prove-the-thump gates; the high-pass/subtraction layer was retired with it.

已被替代：heuristic-v1.1（约 55Hz 高通 + 谱减 + SNR 门，2026-10-21 随 `32fd6b0` 上线）走的是"减掉房间频谱、抢救被噪声埋没的敲击"路线。真机实测发现纯噪声录音仍会给出结论，v2 起改为"先证明敲击存在"的门控路线，高通/谱减层随之退役。

Known physical limit: a genuinely resonant low-frequency knock in the environment (e.g. a hollow door at ~95 Hz) is acoustically indistinguishable from an overripe melon and will still read OVERRIPE.

已知的物理极限：环境里真实的低频共振声（如空心门被敲出约 95Hz 闷响）与过熟瓜声学上无法区分，仍会判为过熟。

### 2.3 Forced Update & Launch Flow (VersionGate) 强制更新与启动流程（VersionGate）

- Launch shows a 3-second splash (the app icon enlarged, the app name, the version number, and "powered by xgao&sgao"). The splash doubles as the server-interaction window: the version check starts with the launch, and the splash lifts only when at least 3 seconds have elapsed AND the check has concluded (the request timeout stays 10 s; on a slow network the splash waits for the verdict, up to that cap). The home screen therefore never flashes before an update prompt.

- 启动显示 3 秒启动页（放大的 App 图标、应用名、版本号与 "powered by xgao&sgao"）。启动页同时是与服务器交互的窗口：版本检查随启动发出，启动页须等"满 3 秒且检查已了结"才揭开（请求超时保留 10 秒；网络慢时启动页等结论，最长等到超时上限）。因此不会出现主页闪现后又弹更新页。

- If `updateAvailable` or `forceUpdate` is true, a blocking full-screen update page replaces the app (non-dismissible); its button jumps to the App Store via the policy's `updateUrl` (to be configured server-side after listing; currently empty, button disabled).

- `updateAvailable` 或 `forceUpdate` 为真 → 全屏拦截更新页（不可关闭），按钮跳 App Store（地址取策略中的 `updateUrl`，上架后在服务端配置填入，现为空、按钮禁用）。

- If the policy cannot be fetched, the app proceeds (fail-open) — a server outage never locks users out.

- 拉不到策略时 fail-open（放行），不因服务器故障锁死用户。

## 3. Server 服务端

| Endpoint 端点 | Purpose 用途 |
|---|---|
| `GET /api/health` | Health check (k8s probe) 健康检查（k8s 探针） |
| `GET /api/v1/version/getclientversion?currentVersion=x.y.z` | Returns the version policy: latestVersion / minSupportedVersion / updateAvailable / forceUpdate / updateUrl / creditPerAd (version comparison is numeric per segment, missing segments padded with 0) 返回版本策略：latestVersion / minSupportedVersion / updateAvailable / forceUpdate / updateUrl / creditPerAd（版本比较为逐段数字比较，缺段补 0） |

Key configuration (`application.properties`):

关键配置（`application.properties`）：

- `melonthump.client.latest-version`: **never edited by hand** — CI injects it from the iOS project's `MARKETING_VERSION` at image build time (see §4). The local default is only a fallback.

- `melonthump.client.latest-version`：**不手动改**。CI 构建镜像时从 iOS 工程 `MARKETING_VERSION` 注入（见 §4）。本地默认值仅作 fallback。

- `melonthump.client.min-supported-version`: the manually maintained hard floor; below it an update is forced (kept for grace periods).

- `melonthump.client.min-supported-version`：手动维护的硬下限，低于它强制更新（留宽限期用）。

- `melonthump.client.update-url`: the App Store link, to be filled in after listing.

- `melonthump.client.update-url`：上架后填 App Store 链接。

- `melonthump.client.credit-per-ad`: credits granted for one completed rewarded ad (default 1). **-1 declares a free day**: for the rest of that day — counted by the client's local date when it fetched the policy — the app is unlimited and shows no ads. Ops flips the value in config and redeploys to run one; the client consumes the field once the credit/ad features land.

- `melonthump.client.credit-per-ad`：用户看完一个激励广告可得的 credit 数（默认 1）。**设为 -1 即“免费日”**：以客户端拉取策略时的设备本地日期为准，当天剩余时间内无限使用且不显示广告。运营时改配置并重新部署即可开启；客户端的 credit/广告行为将在相应功能落地时消费此字段。

Note: the repository's git release tags (semantic-release, currently v1.4.0) are the **server's** version line, decoupled from the app version (`MARKETING_VERSION`, currently 1.0); the version gate only honours the app line — never mix them.

注意：仓库的 git 发布标签（semantic-release，现 v1.4.0）是**服务端**的版本线，与 App 版本（MARKETING_VERSION，现 1.0）脱钩；版本门只认 App 版本线，切勿混用。

## 4. Infrastructure & CI/CD 基础设施与 CI/CD

- **Cluster**: the homelab VM100 k3s single node; namespaces `melonthump-prod` / `melonthump-dev`; one manifest per environment, `k8s/prod|dev/melonthump-server.yaml` (Namespace + Deployment + Service, probe `/api/health`).

- **集群**：homelab VM100 k3s 单节点；命名空间 `melonthump-prod` / `melonthump-dev`；每个环境一份清单 `k8s/prod|dev/melonthump-server.yaml`（Namespace+Deployment+Service，探针 `/api/health`）。

- **Images**: `ghcr.io/lookmail88/melonthump-server` — prod tagged `:latest`, dev tagged `:dev`, plus `:v<release>` tags.

- **镜像**：`ghcr.io/lookmail88/melonthump-server`，prod 打 `:latest`、dev 打 `:dev`，另有 `:v<release>` 标签。

- **Releases**: ArgoCD syncs by branch (main → prod, development → dev); applications are Synced/Healthy.

- **发布**：ArgoCD 按分支同步（main→prod、development→dev），应用状态 Synced/Healthy。

- **Ingress**: Cloudflare Tunnel (remotely managed; cloudflared runs in kube-system in-cluster). The two Published applications' Service entries must be full FQDNs: `http://melonthump-server.melonthump-prod.svc.cluster.local:8080` (dev likewise with its namespace). A typo here (melonthupm / a missing `.svc`) once caused public 502s — debug from the tunnel logs.

- **入口**：Cloudflare Tunnel（远程管理模式，集群内 cloudflared 在 kube-system）；两条 Published application 的 Service 必须写全 FQDN：`http://melonthump-server.melonthump-prod.svc.cluster.local:8080`（dev 同理换命名空间）。曾因手误拼错（melonthupm / 漏 `.svc`）导致公网 502，以隧道日志为准排查。

- **CI** (`.github/workflows/melonthump-prod.yaml` / `melonthump-dev.yaml`): triggers on pushes to main/development that touch `server/**` or `ios/MelonThump.xcodeproj/**` → semantic-release versions and tags → Maven build gates → reads MARKETING_VERSION → Docker build (the version policy injected as a build-arg) and push to GHCR.

- **CI**（`.github/workflows/melonthump-prod.yaml` / `melonthump-dev.yaml`）：push 到 main/development 且 `server/**` 或 `ios/MelonThump.xcodeproj/**` 有变化时触发 → semantic-release 发版打标签 → Maven 构建把关 → 取 MARKETING_VERSION → Docker 构建（build-arg 注入版本策略）并推 GHCR。

- **Branch rule**: day-to-day development happens on the lowercase `development` branch; **main only accepts PR merges** (same convention as Retax).

- **分支规矩**：日常开发在小写 `development` 分支；**main 只接受 PR 合并**（同 Retax 约定）。

- **Permissions note**: the GitHub App (Meta Muse AI) has no Workflows permission, so workflow files can only be edited locally and pushed by the user; the Mac clone is shared by the xuyanggao and pepper users, with `core.sharedRepository=group` set and whole-repo ownership standardised on xuyanggao:staff.

- **权限备忘**：GitHub App（Meta Muse AI）无 Workflows 权限，workflow 文件只能在本地改后由用户 push；Mac 克隆为 xuyanggao 与 pepper 双用户共用，已设 `core.sharedRepository=group`，全仓库所有权以 xuyanggao:staff 为准。

## 6. Known Limitations 已知限制

- The ripeness thresholds (160/280 Hz) are placeholders, not yet calibrated on real melons — the current top priority is collecting labelled samples to calibrate them.

- ripeness 阈值（160/280Hz）是占位值，未用真实瓜样本校准 — 当前第一优先级是采集带标注样本校准阈值。

- The analyzer gate parameters (prominence 10 dB, crest 18 dB, SNR 6 dB, band 60–600 Hz, trim windows) are first-cut empirical values, validated on synthetic samples and real-device field tests; they will be regressed as real labelled samples arrive.

- 分析器门控参数（突出度 10 dB、尖锐度 18 dB、SNR 6 dB、频带 60–600 Hz、掐头去尾窗口）为首版经验值，经合成样本与真机实测验证，随真实标注样本积累回归调整。
